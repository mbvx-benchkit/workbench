# WORKBENCH

個人用のHTML / CSS / TypeScript製ツール集。GitHub Pagesでも動作する静的Webアプリです。

## ビルド・テスト

```bash
npm ci
npm run verify
```

## バックアップと復元

ホーム画面から暗号化バックアップ（`.wbenc`）を作成します。復元では旧ZIP（v1/v2）も読み込めます。
対象はDOCUMENT BUILDERのテンプレートとPDF履歴、RED INDEX、定型印刷物です。
**GOSPLAN13の自動保存とINVENTORY BATCHのCSVは従来から意図的に対象外です。**
それぞれの画面で提供されるJSON/CSV保存機能を利用してください。

復元時には元データをIndexedDBの`workbench-restore-recovery`に一時退避します。
失敗・中断した場合、ホーム画面の「元のデータを復旧」から元に戻せます。
復元が完了した場合は一時データを削除します。複数DBをまとめた単一の
トランザクションはWeb API上不可能なので、復旧ジャーナルを採用しています。

バックアップの上限は展開後512MiB、1ファイル64MiB、画像32MiB、JSON 20,000,000バイト、エントリー12,000件です。
出力時にPDFを一括取得する前に概算を検査し、ZIP生成時にも厳密に検査します。
PDF履歴は出力・復元とも最大5,000件で、5,001件以上のバックアップは作成しません。
この上限を超える場合は作成できません。

## 保存データとバックアップの整合性

定型印刷物のPDFは64MiB以下、プレビュー画像は32MiB以下で登録できます。PDFは実データのヘッダー・終端を、画像はPNG/JPEG/WebPのシグネチャを確認し、保存形式を正規化します。古いレコードのMIME情報が空または不正でも、バックアップ時にはファイル実体から判定して整え、復元可能なアーカイブを生成します。破損ファイルがある場合はバックアップを出力せず、対象名と原因を表示します。既存データは自動で変更しません。

DOCUMENT BUILDERのPDF履歴は5,000件まで保存でき、履歴PDF単体の容量上限は64MiBです。すでに上限を超えて保存された過去のデータは自動削除しないため、バックアップするには履歴を整理してください。

GOSPLAN13のJSONは全48面分の画像をBase64として含めるため、**出力と読み込みで共通の64MiB上限**を設定しています。上限超過のJSONは出力を止め、復元不能なファイルを生成しません。INVENTORY BATCHのCSV読込上限は10MiBです。

## 個人情報保護

`.gitignore` とコミット前フックでファイル種別を検査し、ソース中の典型的な認証情報も検出します。
検査は万能ではなく、個人情報や未知の秘密情報はpush前に人が確認してください。
ソースコードのZIP配布には `scripts/export-public-source.sh` を使用します。

## プロジェクト構成

WORKBENCHはGitHub Pages上で動作する静的なツール集です。HTML/CSS/TypeScriptを使用し、アプリ本体の処理はブラウザで実行します。

| ディレクトリ | 用途 |
| --- | --- |
| `src/` | ホーム画面、暗号化バックアップ、定型印刷物管理 |
| `gosplan13/src/` | JANコード入力、チェックデジット、ラベル生成、保存と印刷 |
| `inventory_batch/src/` | 棚卸CSV解析、JAN/EAN-13コード描画、一覧と印刷 |
| `red_index/src/` | 割引不可商品リストの編集、プレビューと印刷 |
| `document_builder/src/` | テンプレート編集、文書作成、PDF保存・印刷履歴 |
| `css/` | 共通ヘッダー、ボタン、トグル、フッター等のスタイル |
| `*/dist/`, `dist/` | ビルド済みJS。GitHub Pagesへの公開に必要なのでコミット対象 |
| `scripts/` | ビルド情報生成、回帰テスト、機密ファイル検査 |

### モジュール分割の原則

- `main.ts` などの入口は初期化と各機能の接続を担当し、画面表示・データ処理を可能な範囲で分離します。
- `templates/`, `history/`, `pdf/`, `barcode/`, `csv/` などは機能別の実装です。
- 細かすぎた `__modules__/*/{models,helpers,lookup,...}.ts` は、機能ごとに `*-utils.ts`, `*-support.ts`, `archive-types.ts` 等へ統合しました。ビルド生成物内の同名ファイルも `npm run build` により更新されます。
- 公開関数の名前、保存データの形式、バックアップ互換性はリファクタリング前と同じです。
- ブラウザ内の保存には現行のIndexedDB等を使用しています。変更前にユーザーデータのバックアップを取ってください。

### バージョンとビルド日時

`package.json` の `version` が全画面のフッターに表示されるWORKBENCHのバージョンです。`npm run build` 時に `scripts/generate-build-info.mjs` が `dist/workbench-build-info.js` を生成し、フッターへ日本時間のビルド日時を表示します。

パッチバージョンを上げる場合：

```bash
npm version patch --no-git-tag-version
npm run check
npm run build
npm run test:workbench
```

新しく作られた `dist` 配下のJSも、`git add` とコミットの対象に含めます。

### 開発・検証フロー

```bash
npm ci
npm run check
npm run build
npm run test:workbench
git diff --check
bash scripts/check-git-sensitive-files.sh --staged
```

`npm run test:workbench` にはフッターのビルド情報検証も含まれます。

PDFの印刷レイアウト、ファイル選択、ダイアログの操作、復元後の状態などは、ビルドと単体テストに加えてブラウザでも確認してください。


## 複数タブの保存とバックアップ復元

WORKBENCHは、同じオリジンの複数タブ間で **Web Locks API** の共通ロック
`workbench:data-integrity:v1` を利用します。定型印刷物、DOCUMENT BUILDERの
テンプレート・PDF履歴・選択状態、GOSPLAN13の自動保存、RED INDEXの自動保存は
共有ロックの下で書き込みます。バックアップ作成時のスナップショット読み取りと、
バックアップ復元・復旧・ロールバックは排他ロックを取得します。

復元開始時にはブラウザ保存領域に更新世代を記録します。復元前から開いていた
別タブから保存しようとすると、古い編集内容で復元データを上書きしないよう
保存を拒否して再読み込みを案内します。途中で復元が中断した場合は通常の保存を
停止し、ホーム画面の「元のデータを復旧」から排他ロック付きで復旧できます。復元終了時の中断で**ジャーナルが削除済み・マーカーのみ残った場合**も、復旧画面に解除操作を表示します。
旧バージョンで作られた復旧ジャーナルが残っている場合も通常の保存を拒否します。

Web Locks APIのないブラウザでは、保護されない書き込み・復元を実行せずエラーを
案内します。保存機能を使う場合は対応ブラウザを利用してください。
**このロックへ参加しない旧バージョンのタブは保護できないため、更新直後の
復元作業では古いタブをすべて閉じ、最新バージョンで開き直してください。**

`npm run test:workbench` にはタブ間の書き込み待機、排他復元、復旧記録、
古いタブからの保存拒否、非対応ブラウザでの停止の回帰テストを含みます。

## テンプレートのインポートと更新

DOCUMENT BUILDERで文書JSONを読み込んだとき、同じIDのテンプレートが登録済みなら、その現在のテンプレート設定を維持し、文書の入力値のみを読み込みます。過去の文書JSONが現在のテンプレート設定を上書きすることはありません。未登録IDの追加にはIndexedDBの`add()`を使い、別タブの追加と衝突した場合も上書きせず拒否します。

テンプレートの追加・編集がIndexedDBで完了した後に画面更新が失敗した場合は、保存済みであることを通知して再読み込みを案内します。選択テンプレートの保存はタブ内で直列化し、古い選択要求が新しい選択内容を上書きしないようにします。


## DOCUMENT BUILDER: 暗号化PDF履歴

DOCUMENT BUILDERのPDF出力履歴は、ほかのツールや文書テンプレートと独立した**履歴専用パスワード**で保護します。
初回の履歴閲覧または履歴保存時に、12文字以上のパスワードを設定してください。ブラウザを再読み込みすると再入力が必要です。パスワードはサーバーやブラウザの永続保存領域には保存しません。

PDF本体と履歴の宛先・ファイル名は、PBKDF2-SHA-256（31万回）で導出した鍵とAES-256-GCMで暗号化してIndexedDBに保存します。暗号化にはレコードごとに別のランダムIVを用います。履歴一覧では必要なメタデータだけを復号し、PDF本体はダウンロード時にだけ復号します。旧平文履歴は最初のロック解除時に順次移行し、中断しても再開できます。

**履歴パスワードを忘れると、暗号化PDF履歴を復元できません。** 現在のパスワードが分かる場合は、既存履歴を保持したまま変更できます。パスワードを忘れた場合は履歴を初期化できますが、暗号化済みの履歴は削除されます。履歴の元PDFを安全な場所にも保管してください。

WORKBENCH全体バックアップはv3形式からPDF履歴を暗号化状態のまま格納します。バックアップの外側にも従来の暗号化がかかり、履歴のパスワード設定はバックアップとともに復元されます。復元後の履歴には**バックアップ作成時の履歴専用パスワード**が必要です。従来のv1・v2バックアップも引き続き読み込み可能で、v2に含まれる平文履歴は、復元時に現在の履歴専用パスワードで暗号化して保存します。

暗号化への移行前の旧WORKBENCHバックアップには平文履歴が含まれ得るため、古いバックアップの管理にも注意してください。また、通常のPDFダウンロード先に保存したPDFは、本機能の暗号化対象外です。


## DOCUMENT BUILDER：暗号化PDF履歴のパスワード管理

DOCUMENT BUILDERのPDF履歴だけを専用パスワードで暗号化します。テンプレートとほかのツールのデータは対象外です。

- 初回利用時は12文字以上のパスワードを設定します。履歴画面の「パスワードを変更」から、現在のパスワードを入力して変更できます。既存の履歴PDFとメタデータは保持され、再暗号化されます。
- 変更時は、古い暗号文を保持したまま新パスワード用の暗号文を一時保存し、最後にIndexedDBの同一トランザクションで切り替えます。容量不足などで失敗した場合、古いパスワードが有効なまま残ります。一時的に保存領域を追加で使用します。
- パスワードを忘れた場合は解除画面の「パスワードを忘れた場合」から、件数と削除対象を確認し、確認文字を入力して**このブラウザのPDF履歴を完全に削除**できます。暗号化された履歴を復号・復旧することはできません。テンプレートやほかのWORKBENCHデータは削除しません。
- 以前に書き出した暗号化バックアップは、パスワードを変更・初期化しても変更されません。古いバックアップの履歴を開くには**バックアップ作成当時の履歴パスワード**が必要です。
- 新しい画面のスタイルは`document_builder/css/history-vault.css`にあります。DOCUMENT BUILDERとホーム画面（バックアップ時の履歴移行）のHTMLから読み込み、履歴専用のダイアログだけに適用されます。


## PDF履歴の自動入力・旧データ移行

履歴専用のパスワード欄には、ほかの機能と混同しにくいフォームID・入力欄名・固定の識別名 `workbench-pdf-history` を付与しています。解除時は `current-password`、新規設定・確認時は `new-password` を指定します。ブラウザやパスワードマネージャーによって保存・自動入力の動作は異なり、必ず自動入力されることを保証するものではありません。同じGitHub Pagesのオリジン上にあるため、完全に独立したWebサイトとして扱われるわけではありません。

旧バージョンでIndexedDBに平文保存されていたPDF履歴は、初回パスワード設定・解除のときに、PDF本体と宛先・ファイル名を1件ずつ暗号化して上書きします。移行中は件数を表示し、完了後も確認表示が残ります。失敗・中断時には次回解除で残件を再移行します。移行が完了した後のIndexedDB上には旧平文の履歴レコードを残しません。ただし、ブラウザ内部の物理的な残存領域、旧バックアップ、ダウンロード済みPDFの消去までは保証されません。

ファビコンは共通ヘッダーの四分割グリッドと同じ形・色を背景透過の `favicon.ico` に収録し、全5画面から参照します。`.gitignore` の画像除外にはルートの `favicon.ico` だけ例外を設けます。
